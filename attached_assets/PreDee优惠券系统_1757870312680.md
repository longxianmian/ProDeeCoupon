# 泰国 H5 优惠券系统开发文档（ProDee 项目）

---

## 一、项目目标
搭建一个基于 **H5 落地页** 的优惠券系统，结合 **LINE Login** 实现用户一键登录与私域沉淀，支持多语言（中/英/泰），并具备后台运营管理功能（门店管理、活动管理、核销管理、活动数据分析）。

---

## 二、系统架构
- **前端（用户端 H5）**：Vue3 / React 开发，移动端优先设计。
- **后端**：Node.js (Express) 或 Spring Boot，RESTful API。
- **数据库**：MySQL 或 PostgreSQL。
- **国际化**：统一 i18n 管理，支持中文/英文/泰文三语切换。
- **消息推送**：LINE Messaging API。
- **存储**：Replit 存储桶（Object Storage）。

---

## 三、用户端功能

### 1. 优惠券详情页（见截图）
- **顶部**：图片/轮播展示。
- **活动信息**：标题、原价、优惠价、节省金额。
- **倒计时**：剩余时间（自动计算）。
- **数量显示**：剩余数量（动态更新）。
- **领取按钮**：
  - 未登录：提示「用 LINE 一键登录」。
  - 已登录：领取成功 → 写入数据库 → 推送消息到用户 LINE OA。
- **附近门店**：
  - 显示参与门店（后台活动绑定门店）。
  - 用户定位后，展示最近 3 家，含门店图片、名称、距离、导航按钮（Google Maps API）。
- **使用规则**：折叠展开。

### 2. 我的优惠券页
- **入口**：LINE OA 底部菜单「我的」。
- **展示**：
  - 已领取的优惠券卡片。
  - 每张卡片包含：优惠金额、有效期、核销二维码、6 位数字核销码、门店导航按钮。
- **核销二维码/核销码**：
  - 二维码：嵌入 coupon_id + user_id + 签名。
  - 备用 6 位数字核销码（便于人工输入）。
- **状态管理**：已领取 / 已使用 / 已过期。

### 3. 登录与关注
- **一键登录**：集成 LINE Login。
- **关注引导**：领取前提示“请关注 ProDee 频道以保存优惠券”。
- **校验**：后台记录 is_following，未关注时拒绝领取。

### 4. 多语言支持
- 界面文本、动态内容均支持 **中/英/泰** 三语切换。
- 登录/领取时提示语自动跟随用户语言设置。

## 四、运营后台功能

### 1. 门店管理
- 新建/编辑门店：名称、地址、经纬度、图片、编码。
- 支持门店搜索、编辑、下架。
- 地址录入时调用 **Places API (Autocomplete)** 提供地址自动补全。
- 提交后调用 **Geocoding API** 转换为经纬度并存储。

### 2. 活动管理
- 新建/编辑活动：标题、描述、图片、原价、优惠价、数量、有效期。
- 活动绑定门店（选择多个）。
- 活动状态：进行中 / 已结束。

### 3. 核销管理
- **核销员授权**：
  - 绑定门店店员的 LINE ID。
  - 授权后可用 H5「工作台」进行扫码核销。
- **核销入口**：
  - 扫码核销（用户二维码）。
  - 手动输入 6 位数字核销码（兜底方案）。
- **核销日志**：记录 coupon_id、user_id、store_id、verifier_id、时间。

### 4. 活动数据（新增）
- **按活动维度统计**：
  - 活动名称
  - 总发行量 / 总领取数 / 总核销数
  - 剩余数量
- **按门店维度统计**：
  - 门店名称
  - 门店核销总数
  - 店员核销明细（店员 LINE ID / 姓名 / 核销数）
- **按时间维度筛选**：
  - 日期区间（本日 / 本周 / 本月 / 自定义）
- **导出报表**：
  - 导出 CSV / Excel，用于门店对账和店员提成计算

### 5. 用户与数据分析
- 用户领取记录查询。
- 按门店、活动、时间统计领取/核销数据。
- 导出 CSV 报表。

### 6. 国际化后台
- 菜单与内容统一支持多语言，不分前后台单独实现。

## 六、存储方案
- **使用 Replit 提供的存储桶（Object Storage）** 存放：
  - 活动图片（Banner/轮播图）
  - 门店图片
  - 用户上传的图片/视频（扩展）
- 存储桶路径通过环境变量配置，例如：
  ```env
  STORAGE_BUCKET_URL=https://storage.replit.com/<bucket-name>
  ```
- 后台上传内容时，直接写入 Replit 存储桶，生成 URL 存数据库。
- 前端访问时，直接引用存储桶 URL。

## 七、Google Maps API 对接方案

### 1. 后台门店创建
- **Places API (Autocomplete)**：输入地址时自动补全，减少录入错误。
- **Geocoding API**：提交后将地址转换为经纬度，存入数据库。 

### 2. 用户端优惠券详情页
- **用户定位**：浏览器 geolocation 获取当前用户 lat/lng。
- **Distance Matrix API**：计算用户到所有门店的距离，选最近 3 家显示。
- **导航按钮**：点击后跳转 Google Maps 导航：
  ```
  https://www.google.com/maps/dir/?api=1&destination=<lat>,<lng>
  ```

### 3. 成本优化
- 门店创建时的 **Geocoding API** 调用只执行一次并存库，不会重复计费。
- 前端用户端的 **Distance Matrix API** 按需调用（只在详情页打开时请求）。
- 使用 Google Maps 静态链接跳转导航（免费），避免重复调用地图渲染 API。

## 九、LINE OA 底部菜单动态展示方案

### 1. 普通用户
- 底部菜单显示：
  - 活动
  - ProDee（关于我们）
  - 我的（我的优惠券）

### 2. 授权店员
- 当 LINE ID 在后台核销员授权名单中时，OA 菜单切换为：
  - 活动
  - ProDee（关于我们）
  - 工作台（核销入口）

### 3. 实现方式
- 使用 **LINE Rich Menu 多套方案**：
  - 普通用户 → 绑定菜单 A
  - 店员用户 → 绑定菜单 B
- 后台通过 Messaging API 根据用户 LINE ID 调用 API 切换绑定的菜单。

### 4. 好处
- 普通用户界面简洁，不会误点。
- 店员登录后自动多出「工作台」入口，角色清晰。
- 提高安全性，避免未授权用户探测入口。

## 十、开发注意事项
1. **隐私政策 & 使用条款**：必须开发 `/privacy` 和 `/terms` 页面，挂在页脚，并在领取时提示。
2. **扫码核销**：主力方式 = H5 店员扫码二维码；兜底方式 = 手动输入 6 位数字核销码。
3. **安全性**：核销码需包含校验（如活动ID+用户ID+CRC8），并且固定长度 6 位。
4. **幂等性**：同一张券只能核销一次。
5. **国际化**：所有文案从 i18n 文件加载，不允许硬编码中文。
